API Reference

Welcome to the official API documentation for api21. A minimal, high-performance REST API backend engine built with NestJS, TypeScript, PostgreSQL, Redis, and BullMQ background workers.

Architecture Summary

Designed for low latency, high concurrency, and complete horizontal scalability:

  • Server Framework: NestJS modular architecture compiled via TypeScript.
  • Relational DB: PostgreSQL managed with Knex connection pooling and auto-migration capabilities.
  • Caching & Rate Limiting: Redis-backed distributed sliding window rate limiter.
  • Background Queue: BullMQ queue engine for async background job execution with Bull Board metrics UI.

Rate Limiting

All endpoints under the /api/v1/ path are protected by a sliding window rate limiter backed by Redis. This prevents service abuse and guarantees backend stability.

Header Description
X-RateLimit-Limit Maximum allowed requests per client IP in a 15-minute window (Default: 200).
X-RateLimit-Remaining Number of remaining requests available for your client IP within the current window.

Exceeding the limit results in an HTTP Status 429 Too Many Requests response payload:

{
  "error": "Too many requests, please slow down."
}

Health Check

GET
/api/v1/health

Returns system and connection diagnostics for core dependencies (PostgreSQL, Redis, BullMQ). Ideal for container orchestrator readiness checks.

Response Format

{
  "status": "healthy",
  "services": {
    "database": "connected",
    "redis": "connected",
    "bullmq": "connected"
  }
}

Get Users

GET
/api/v1/users

Retrieves an array of all registered user objects from the database.

Query Parameters

No query parameters required.

Create User

POST
/api/v1/users

Creates a new user record in PostgreSQL. Body payload must be JSON.

Request Body Parameters

Parameter Type Required Description
name string Yes Display name of the user (max 255 characters).
email string Yes Unique valid email address.

Delete User

DELETE
/api/v1/users/:id

Permanently deletes a user record by primary key ID.

Path Parameters

Parameter Type Required Description
id integer Yes Unique primary key ID of the target user.

Enqueue Job

POST
/api/v1/jobs

Enqueues a new background job into BullMQ queue processor.

Request Body Parameters

Parameter Type Required Description
type string Yes Name/type of the job operation to execute.
payload object No JSON metadata or context payload passed to background worker.

Job Status

GET
/api/v1/jobs/:jobId

Inspects the current state (active, completed, failed, delayed) of an enqueued background job.

Path Parameters

Parameter Type Required Description
jobId string Yes Unique job identifier returned upon enqueuing.

Queue Metrics

GET
/api/v1/jobs/metrics

Returns real-time BullMQ queue metrics including active, completed, failed, and waiting counts.
